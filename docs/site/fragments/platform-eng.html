What CI/CD automates from here

The manual steps above map directly to CI jobs: run fe check on every push, run fe publish on merge to main, and update the route in platform.json via a CD step. Each team does this independently for their own MFE.

۞ Cloud deployment

CDN and caching

JIT-compiled artifacts are served with Cache-Control: immutable because the URL includes the version. Put a CDN in front of fe serve with the following origin configuration:

  • Forward all /bundle/ requests to the JIT server origin.
  • Cache responses that include Cache-Control: immutable at the edge.
  • The first request per version compiles; every subsequent request serves the CDN copy.

Config management

Two config files serve different audiences:

File Who edits it What it controls
fe.config.json Platform team JIT plugins, storage adapters, shell directory
platform.json CD pipeline (or platform team) Routes and package versions

The platform team controls the JIT server configuration. MFE teams never edit fe.config.json. The CD pipeline updates platform.json when a new version is published.

Rollback

Because each publish creates a new immutable URL, rollback is a one-line change to platform.json. Old versions remain available forever. There is no "deploy" step that overwrites a previous version.

The runtime reads the updated manifest on the next page load. No server restart required.

Monitoring and observability

The JIT server logs each compilation with timing and cache status. Integrate these logs with your observability stack:

  • Cache hit rate — should approach 100% after warmup.
  • Compilation time — typically 50-200ms per MFE.
  • Error rate — should be near zero; investigate any spike.

Authentication

The platform does not prescribe an auth mechanism. MFEs can implement their own auth flows, or the shell can inject an auth context into each render() call via the props argument.

Each MFE receives the auth state in its render() props.

Plugin development

Plugins can swap any adapter at bootstrap time. Common use cases:

  • Artifact storage — replace local uploads/ with S3, GCS, or Azure Blob.
  • Config provider — read fe.config.json from environment variables or a remote API.
  • CLI commands — add new commands like fe deploy or fe status.

Plugins run after built-in adapters are initialized, so they can freely override any adapter.
